## 2. Proposed UI integration (same visual language as existing service panels)
Preserve the existing glass/shaded HUD, no independent app page or duplicate Questbook. Reuse actual template assets where supplied; no recreation of artwork required by this specification. Layout proposal: left quest categories and list, center selected narrative/objectives, right earned/eligible reward and contextual actions; on narrow screen use sequential detail view instead of shrinking text. Preserve existing L service toggle and remap semantics after source verification; ESC closes current overlay before world pause, keyboard typing/choice focus must not send combat actions. No auto-opening on every progress event. Questbook is read-only state plus scoped intents: track/untrack, inspect, choose approved dialogue response, confirm readiness, retry or return. Never direct complete, give reward, bypass clue, spawn or teleport buttons. Tracking is presentation preference only. Show chapter title only after activation; upcoming unknown chapters hidden. Optional activities tab never gates M01–03. Discovery tab empty or explanatory until actual eligible discovery exists; no reveal markers for hidden content. Use captions, keyboard/controller navigation, touch safe area and reduced motion; actual hit volumes unchanged.

## 4. Dialogue and input ownership
One interaction owner resolves nearby eligible actor and actual source anchor. Display speaker, readable text and choices only when authored for current stage. On movement away cancel uncommitted choices and preserve delivered warning/observations; on reopen resume safe appropriate line rather than restarting combat. Voice off/subtitles and reduced motion use equivalent actual cue; skip records essential journal only when source permits, never marks help/observation/interrupt by skipping. Distinguish delivered protective warning, actual wolf observation, actual warning exchange, and readiness. During active combat block unrelated dialogue service interruptions or use existing safe policy; no global pause assumed. On focus loss release held input, not grant success. Async portrait/voice requests scoped to session and actor; late callback cannot re-open old dialogue or advance another character. Missing portrait uses neutral silhouette or text; no placeholder identity leak. Dialogue option strings are presentation, use a known action reference internally; validate current quest/actor/phase/anchor/epoch before accepted action. No browser event listener directly granting entitlement.
## 5. Proposed read model and reward contract
Read model fields: source catalog ID and version; active chapter and approved player-facing label; current objective labels/status; optional evidence; eligible choices; tracking preference; encounter status; reward status; recovery availability; provenance (synthetic/local/remote verified); monotonic revision. Immutable snapshot for presentation, not grant authority. Data adapters own validated state and expose intents with bounded inputs; reject unknown IDs and stale snapshots. Preview model must remain memory-only with synthetic role and no live SDK, storage or inventory imports. Real mode distinguish local device progress from verified server ledger; never silently downgrade a remote-verified character to local grant after failure. Preserve existing guest-only entry; no new login or authority bypass.
Reward contract proposal: catalog-defined entitlement per actual eligible outcome and cycle, not client-selected item/amount. Record actual victory and pending entitlement atomically or equivalent durable idempotent ledger; reconcile by stable semantic key (character scope + story source + cycle + reward rule version/eligibility scope agreed before implementation), not a new random transaction ID for each retry. On durable grant return exact receipt and stable item instance refs, do not recreate consumed/sold equipment. Before applying response check identity/session; stale response may be reconciled only to original authorized owner, not current character. Confirmed grant projects onto inventory, XP or skill UI; pending or blocked state is truthful and never rolls a second reward. M01 help grants optional goodwill, no permanent item proposed. M03 temporary training loaner only if valid weapon absent, never force equip; exact final disposition and XP/loot values remain pending source balancing. No grant in preview, no new permanent gear invented. M03 victory vs aftermath separate; no extra reward for skip/continue. For later D01–50 preserve actual paired focus, relic entitlement, existing older item and required second vista; generic material collection toast cannot complete discovery. No optional D/S enabled in P01.
## 6. Notifications and save/recovery
Use existing HUD notification area for confirmed actual events; dedup semantic event per scope, no toast on render/reload alone. Quest changed notification only on accepted revision; discovery toast only on confirmed appropriate outcome; gear/XP notice only after verified application. Pending message neutral, no fake value, failed request offers appropriate retry. Questbook history remains source for missed toast. Safe checkpoint excludes transient overlay focus, active animation, pending attack, camera tween and mock reward. R135 safe precombat/defeat state and epoch rules retained. On invalid pose/anchor, use last validated safe local anchor or stop; never restore arbitrary world position.
