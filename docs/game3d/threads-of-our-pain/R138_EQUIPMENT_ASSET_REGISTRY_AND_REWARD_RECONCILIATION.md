## 2. Three independent contracts
Definition: existing catalog template and version, slot/role, rarity, level, stats, enhancement, set and eligibility rules; authoritative existing logic. Instance: stable owned instance ID, character scope, definition ref, actual advancement, source/grant receipt, equipped/preset state and ownership history. Visual record: logical asset ID, approved icon/model/material/rig/attachment refs, quality availability and version/hash, license/source, bounds and units, resource leases. A visual revision never mutates stats, equipment eligibility, ownership, advancement, sockets, set bonuses, item identity or reward receipts. Do not copy inventoryData seed catalog into a second inventory or roll new instance on render. Preserve existing role rules and balance. No balancing changes to current Ascend/Combine or cap semantics; conflicts between historical design and actual code need separate owner review.
## 3. Proposed asset intake record (logical fields, not runtime schema)
| Field | Required return |
|---|---|
| Logical visual key | Existing definition/piece/model mapping or proposed unassigned alias; actual catalog ID before integration |
| Picture | Actual reviewed path/hash, dimensions, alpha/color space, source/license; authored picture precedence |
| Model | Actual local or approved asset URI/hash, format, scale/axes/pivot and bounds |
| Rig and attachment | Body/rig version, socket, local transforms, carry/combat poses, fitted armor skin weights and verified animations |
| Materials | Texture refs/resolution, alpha mode and required renderer support |
| Quality | Independent Low/Normal variants if supplied, distance LOD separate, no hidden High load |
| Physical role | Visual only unless independently approved physical collider; never infer weapon range from mesh |
| Ownership | Shared/owned leases and disposer, async request generation and session scope |
| Approval | Source revision, actual provenance, permission, test evidence, reviewer and missing-asset fallback |
Use supplied art directly; no regenerated templates or invented paths. Existing picture precedence respects iconUrl/imageUrl/image/thumbnailUrl; missing sword/daggers/bow images may use existing verified family mapping (actual file availability TBD). Other missing icons use neutral existing UI placeholder and text, never a fabricated named item. Review portrait/weapon/armor assets independently; no cross-body identity substitution. For new weapon packs preserve manifest convention or explicit verified adapter. Existing armor mapping helm→helmet, chest→chest, gloves→gloves, legs→pants, boots→boots, cape→cape, wings→wings. Keep dev-only armor out of story rewards and production catalogs. No user-supplied arbitrary executable URLs or remote fetch in preview; validate allowlisted reviewed content/format/size before loading.
## 4. Performance and visual lifecycle proposal
Normal = approved selected-quality model. Low = separate reviewed reduced geometry/material variant, not merely hide original. Hidden = do not request armor model for this presentation; release owned leases, retain safe base body/clothing and same gameplay state. These are proposed Fallen Sky visual modes, not assertion Duelist changes are already deployed or Fallen Sky supports them. Missing Low uses safe approved fallback/neutral visual with honest label, never silently load expensive Normal. Changing graphics mode cannot change owned/equipped state, set bonus, physics, collision/hitbox, role/attack range or quest eligibility. Weapon visibility changes must retain readable attack cues and existing combat ownership; no competitive concealment rule invented. Reuse existing runtime and armor bridge, no second scene/input listener. On equip/quality/body/session change invalidate old load token, resolve exact identity and asset version; release stale result only when owned. Shared caches need lease tracking before disposal; inspect actual texture/skeleton ownership, cache lifetime and renderer recovery. Do not retain hidden loaded mesh merely for performance mode; release resources safely, not active shared assets. UI icon loading independent of 3D models, lazy visible items, safe image failure. Actual resource cost, browser/mobile/backend behavior and repeated swap measurements required; no FPS promise.
## 5. Reward reconciliation and capacity
Observed loot store: 200 bag units then 400 protected personal vault units, checked write, null if both full or storage fails. Equipment store is distinct; do not apply 200/400 to equipment without verified policy. Existing discovery apply code dedups units by bag dropId and calls addLootToInventory then records claim and dispatches events; null return and overflow/previously consumed item cases require explicit reconciliation review. Current characterScopedStorage resolves current identity at call time. Existing equipment add generates an instance if missing, rejects duplicate existing instance, emits and optionally equips; not proof of durable authoritative grant. These observations are potential compatibility gaps, not confirmed exploits, not fixes.
Proposed authoritative flow: validated actual story outcome → stable entitlement key scoped to character/source/cycle and approved reward scope → durable grant/pending record → apply exact item instances or loot dropIds once → reconcile confirmed ledger and correct container → UI confirmed notification. No new random ID on retry of same entitlement; separate request attempt from semantic entitlement. Unknown catalog or wrong actor/phase/identity rejected. Verify actual capacity and persistence, return exact confirmed locations; if full/failure, keep entitlement pending and recover same grant via approved mechanism, no silently lost or duplicate reward. No inventory grant from a picture, asset load, local browser event, arbitrary client quantity or client coordinates. Preserve consumed/sold/destroyed receipt provenance and actual earned gear through NG+; exact repeat eligibility under R84 requires approval. No automatic fallback from remote authority to local grant; preserve guest-only entry. Delayed response must not write into current different character. Authoritative API and transactional reconciliation not yet audited. Do not change live reward service or migrations.
P01 M03: basic temporary loaner only when no valid weapon, no forced equip over existing selection, no live item in isolated fixture. Exact final disposition and XP/loot tuning pending. No D/S optional quests activated during P01. Later paired discoveries retain actual two observations, one younger reward, older existing item and second vista; material node receipts not substitute. Asset arrival does not complete quest.
