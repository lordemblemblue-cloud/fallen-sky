## Authority and dispatch
The UI receives only a detached read view. A separate host capability submits a scoped observation, chapter, receipt ID and expected host revision. A host-injected verifier must return true before a scene bridge is invoked; real evidence must be independently derived from game systems, not arbitrary client booleans. Only the next eligible chapter is accepted; creation of its nested bundle and application of its first event are one proposed in-memory operation. Bridge revisions and observation counts are derived internally. Raw objective/quest completion is not a supported UI operation. Exact receipt retries return current state without replay; conflicting receipt and stale revision rejected; scene duplicates with new receipt rejected. Failed verification/bridge/commit guard leaves current record unchanged. The default commit guard is only a test hook, not storage. No reward or economy interface.

The phase 52 finding that M03 accepts arbitrary reported HP remains unresolved until actual combat-engine authority exists. Verifier injection does not itself prove combat, collision, actor presence or ownership; a malicious or incorrect host could approve invalid evidence. JS closures are not authentication or server security. Actual UI intent must be interpreted separately from verified gameplay outcomes. No binding to GameView, existing store, renderer, Base44 or API.

## Persistence contract required before live use
One canonical campaign aggregate keyed by authenticated owner or validated private guest recovery scope, character slot and campaign; store schema/content/tuning revisions, scene and quest revisions, receipt identity and payload digest, current eligible chapter, active reality, independently owned loadout references and last safe checkpoint. Actual database must enforce unique receipt and atomic conditional write against durable version (or verified single-writer protocol); no separate scene/quest/receipt commits. Validate real events and authorization before writes; a successful local fixture event is never server reward evidence. For transient M03 combat, keep ephemeral state and resume last safe checkpoint with fresh epoch; never serialize unsafe active attack frames as a durable checkpoint. On write interruption, retain last committed aggregate and retry same receipt; reject conflicting payload and stale revision; never overwrite corrupt or foreign saves. No automatic legacy migration. Actual storage API, identity validation, size limits, compaction, two-device conflict handling, independent inventories and reward transactions remain unresolved. Current checkpoint export contains bridge-encoded diagnostic data only, deliberately marked restorable:false: does not include durable receipt ledger, import or recovery protocol.
