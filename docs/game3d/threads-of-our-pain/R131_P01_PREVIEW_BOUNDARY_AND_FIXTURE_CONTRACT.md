## 2. Movement and collision

Do not invoke whole live frame loop in fixture: it writes mastery, combat and checkpoints. Preserve collision-backed floors at stream and ridge; no hidden geometry from old world. playerGlide exists (D49 future), no claim of unlock compatibility. Propose separate preview ground query with explicit null/unloaded result, reference foot level, collision owner and valid floor span; reject null/unsafe upward snap, edge crossing and blocked step rather than invent floor. Long-frame movement substep or equivalent proven collision method pending actual adapter review. Distinguish physical collision, visible geometry and decorative cue. Test stationary/turn/run/retreat, keyboard, mobile and optional click-to-move. Do not create a replacement controller as if compatible; reuse proven pure functions and extract/inject existing movement interface only in authorized engineering task; any standalone camera/geometry stand-in clearly labeled not controller parity.

## 4. Asset and renderer lifecycle
Existing avatar loader has async fallback, disposal traverses skeleton, geometry, material and textures; it assumes ownership, so do not blindly dispose shared assets. GameWorld3D cleanup 5975–6173 flushes live checkpoint, invalidates loads, stops frame and listeners, disposes region/scene and renderer and clears global references. Preview must NOT copy checkpoint flush or global mutations. Use one preview session epoch; own canvas, camera, frame callbacks, input, timers, audio, asset leases and disposers in a local registry. Proposed manifest fields: asset logical ID (not runtime ID), source/license/actual path or placeholder, quality tier, bounds, collision ref, owned/shared resource lease and disposer. Acquire only Low, track pending load token, reject stale callbacks and release their owned resources, never activate unloaded floor; avoid destroy of a shared live renderer. On exit: invalidate session, stop input/frames, detach listeners, stop mixers/audio, release owned scene resources once, then destroy preview-owned renderer/canvas. On failed init/intentional device destroy handle late ready promises and avoid spurious recovery; reuse existing factory/destroy helper where dependency audit permits. Resource counts, repeated mount and memory measured, not assumed from dispose calls. No Mid/High until Low approval; variants not distance LOD; preserve geometry/collision and selected state on switch.
