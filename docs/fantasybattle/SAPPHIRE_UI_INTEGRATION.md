All 48 UI IDs have dedicated render cases. UI text is live HTML; the vector panel backgrounds are reconstructed text-free templates, not pixel-perfect retouches of concept art.
 
## Preview
With the branch checked out, run npm install and npm run dev, then visit /fantasy-battle. Production stays Coming Soon until the existing release flag is deliberately enabled following QA. The other games are unchanged.

## State and scope
Guest data is localStorage, three validated slots, separate namespace. No fabricated saves, no login restoration, no new public server endpoints. Cloud saves are not implemented. A validated portable JSON backup can be exported in Save Game or Load Game and imported from title Settings into a chosen slot with explicit confirmation. Three prototype companions are recruitable after individual Sapphire Wilds victories. The four-member roster, formation and bond screens use real saved state. All share the existing archer rig with distinct palettes and combat roles; unique models, non-bow animation sets and narrative relationship events are still unauthored. Wardrobe now supports four stat-neutral color palettes applied to the existing archer rig, exploration placeholder avatar and portrait preview. These are color variations, not new clothing meshes. Legacy saves without an appearance field use Silver Archer. Boss encounters currently reuse the archer opponent with scaled stats, not a distinct boss model.

## Guest save protection and cross-device transfer
- No changes to authentication, Base44 entities, service roles, server functions or Game 3D's existing guest vault. Fantasy Battle retains three local slots, plain backups and optional password-encrypted backup files. AES-256-GCM with a random 96-bit nonce, random 128-bit salt and fixed PBKDF2-SHA256 (600,000 iterations) via browser Web Crypto. Bounded import envelope and strict profile parser; incorrect password/tamper is rejected before slot mutation. Passphrase is not persisted or transmitted, and no recovery mechanism exists. Plain files and localStorage remain unencrypted; these are user-controlled offline game saves, not authoritative multiplayer data.
- Writes now accept a record stamp; autosave uses the last loaded/saved stamp, manual confirmation and imports use the stamp shown at confirmation. Storage events refresh visible slots without advancing the active session baseline. Conflicts retain the current session and request explicit manual save or export. This is optimistic protection, not an atomic multi-tab transaction; simultaneous read/write across browser processes is still possible. No silent overwrite on known stale records. Existing slot schema unchanged.
- Cross-device transfer is manual: export encrypted JSON, place it in user-controlled cloud storage or transfer it directly, import with the same passphrase. Automatic cloud synchronization is intentionally not enabled. Before any Fantasy Battle cloud vault implementation, separately review Game 3D's guest vault, use a private game-scoped namespace, high-entropy recovery credentials, atomic server revisions, ownership checks, quotas/rate limits, revocation and deployment security tests; never expose another game's records or use a character name as authorization. Do not enable shared public entity permissions or new service-role endpoints on the strength of this draft.
